# 담당자 확인이 필요한 작업

이 문서는 쇼츠 MVP를 배포하기 전에 프로젝트 담당자가 확인하거나 직접 해야 하는 작업을 모은 것입니다. 2026-11-27에 작성했습니다. 아래 작업은 AWS 공용 계정에 리소스를 만들거나, 권한을 바꾸거나, 외부 서비스에 설정을 만드는 일이므로 자동으로 실행하지 않았습니다. 코드, 테스트, `cdk synth`는 이 작업들과 무관하게 끝낼 수 있어서 먼저 진행했습니다.

## 1. 서울 리전에 스택 배포 (`cdk deploy`)

현재 상태는 다음과 같습니다. `infra/`의 CDK 스택은 `cdk synth`까지만 확인했고 배포하지 않았습니다. 서울 리전(`ap-northeast-2`)의 CDK 부트스트랩은 2026-11-27에 끝냈습니다.

배포하면 S3 버킷 2개, DynamoDB 테이블 2개, VPC 1개, ECS 클러스터와 Fargate 작업 정의, Lambda 함수, Step Functions 상태 기계 2개, API Gateway HTTP API, CloudFront 배포, Secrets Manager 비밀 1개, 그리고 이들이 쓰는 IAM 역할이 만들어집니다. IAM 역할을 새로 만들기 때문에 담당자 확인이 필요합니다. 배포할 때 컨테이너 이미지를 빌드하므로 배포하는 컴퓨터에 Docker가 있어야 합니다.

확인할 것은 배포를 실행해도 되는지입니다. 실행 명령과 컨텍스트 값은 `infra/README.md`에 있습니다.

## 2. `marketing.awskr.org` 도메인 연결

CloudFront에 사용자 도메인을 붙이려면 인증서가 `us-east-1`에 있어야 합니다. 스택은 인증서를 만들지 않고 인증서 ARN을 컨텍스트 값으로 받습니다. 그래서 다음 세 가지가 먼저 필요합니다.

첫째, `us-east-1`의 AWS Certificate Manager에서 `marketing.awskr.org` 인증서를 발급합니다. DNS 검증을 쓰면 `awskr.org` 호스팅 영역에 검증용 CNAME 레코드 1개가 추가됩니다. 둘째, 그 인증서의 ARN과 `awskr.org` 호스팅 영역 ID를 배포 명령의 컨텍스트 값으로 넘깁니다. 이 두 값은 저장소에 커밋하지 않습니다. 셋째, 배포하면 스택이 `awskr.org` 영역에 `marketing` 별칭 레코드(A, AAAA)만 추가합니다. 기존 레코드 17개(2026-11-26 조회)는 건드리지 않습니다.

확인할 것은 인증서 발급과 레코드 추가를 진행해도 되는지입니다. 도메인 없이 CloudFront 기본 도메인으로 먼저 배포해 시험할 수도 있습니다. 다만 GitHub 로그인의 콜백 주소가 도메인에 묶이므로, 도메인을 바꾸면 GitHub App의 콜백 주소도 바꿔야 합니다.

## 3. GitHub App 생성과 `awskrug` 조직 설치

로그인은 GitHub App을 씁니다. GitHub App을 만들고 `awskrug` 조직에 설치하는 일은 조직 소유자 권한이 필요하므로 담당자가 직접 해야 합니다. 필요한 설정(콜백 주소, 권한)은 `services/api/README.md`에 있습니다.

App을 만든 뒤에는 클라이언트 ID와 클라이언트 비밀 값, 그리고 직접 만든 세션 서명 키를 배포된 Secrets Manager 비밀에 넣어야 합니다. 비밀의 JSON 키 이름은 `docs/plans/2026-11-27-mvp-backend-contract.md`의 4절에 있습니다. 이 값들을 넣기 전에는 로그인이 동작하지 않습니다.

## 4. 로고 파일 선택

워터마크와 끝 화면에 쓸 로고는 미디어 버킷의 `assets/logo.png`에서 읽습니다. 이 파일이 없으면 로고 없이 렌더링합니다. `awskrug-digital-assets` 저장소의 어느 파일을 쓸지 정해지지 않았습니다. 로컬 시험에는 `gurumi/gurumi-with-title_TP.png`를 썼습니다. 담당자가 파일을 정하면 배포 뒤 버킷에 올립니다.

## 5. Bedrock 전역 추론 프로필 사용

서울 리전에서는 Claude Sonnet 4.6을 전역 추론 프로필(`global.anthropic.claude-sonnet-4-6`)로만 호출할 수 있습니다(2026-11-27 조회). 전역 추론 프로필은 요청을 다른 리전에서 처리할 수 있습니다. 전사문은 공개 밋업의 발표 내용이지만, 한국 밖에서 처리되어도 되는지는 담당자가 판단해야 합니다.

## 6. PR 병합

PR #1(`superlite/shorts-processing` → `main`)은 열려 있고 병합하지 않았습니다. 이 문서가 다루는 추가 작업은 `feat/mvp-remaining` 브랜치에 있으며 푸시하지 않았습니다. 푸시와 PR 생성, 병합은 담당자의 확인을 받은 뒤에 합니다.

## 7. 배포 뒤에 확인할 것

배포해야만 확인할 수 있어서 아직 확인하지 못한 항목입니다. 서울 리전 Transcribe의 한국어 전사 품질과 소요 시간, Fargate에서의 렌더링 소요 시간과 비용, 수 GB 파일의 브라우저 업로드 시간, GitHub 로그인의 전체 흐름(팀 멤버와 비멤버 각각), 영상 1편의 실제 청구 비용이 여기에 해당합니다.
