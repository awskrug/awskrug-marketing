# 첫 구현 범위: 쇼츠 MVP

이 문서는 2026-11-26에 프로젝트 담당자와 진행한 인터뷰의 결정 사항을 기록합니다. 첫 구현(MVP, 가장 먼저 동작하게 만들 최소 범위)은 쇼츠 자동 생성입니다. 슬라이드 동기화 영상과 YouTube 자동 업로드는 쇼츠 MVP 뒤에 만듭니다. 전체 설계는 [architecture.md](architecture.md)에 있고, 이 문서와 내용이 다르면 이 문서의 결정이 우선합니다.

## MVP가 끝났다고 보는 기준

`sns-working-group` 팀 멤버가 `marketing.awskr.org`에 GitHub 계정으로 로그인해 밋업 녹화 영상 파일을 올리면, 서비스가 핵심 구간 후보를 보여 줍니다. 사용자가 후보를 고르면 서비스가 그 구간을 세 가지 화면 구성의 세로(9:16) 쇼츠로 렌더링하고, 사용자가 결과 영상을 내려받을 수 있습니다. 이 흐름이 실제 AWSKRUG 밋업 녹화 영상 1편으로 처음부터 끝까지 동작하면 MVP가 끝난 것입니다.

MVP의 목적은 세 가지 화면 구성을 실제 결과물로 비교해 하나를 고르는 것입니다. 그래서 MVP는 고른 구간마다 세 구성을 모두 렌더링합니다. 구성을 정한 뒤에는 정한 구성만 렌더링하도록 바꿉니다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 첫 구현 기능 | 쇼츠 자동 생성 |
| MVP에 포함 | 웹 화면, GitHub 로그인, 영상 업로드, 전사, 핵심 구간 후보 선정, 후보 선택, 렌더링, 결과 내려받기 |
| MVP에서 제외 | YouTube 자동 업로드, 슬라이드 동기화 영상, 슬라이드 파일 입력 |
| 사용자 범위 | GitHub `awskrug` 조직의 `sns-working-group` 팀 멤버만 로그인 가능 (2026-11-26 기준 5명) |
| 영상 입력 | 브라우저에서 파일 업로드만 지원. YouTube 주소 입력은 지원하지 않음 |
| 핵심 구간 처리 | 서비스가 후보를 보여 주고 사용자가 고른 구간만 렌더링 |
| 쇼츠 화면 구성 | 아래 세 가지를 모두 만들어 비교한 뒤 결정 |
| 브랜드 요소 | 로고 워터마크, 상단 제목 띠, 한국어 자막, 끝 화면 |
| 브랜드 자산 출처 | `awskrug/awskrug-digital-assets` 저장소 |
| 웹 주소 | `marketing.awskr.org` |
| AWS 계정과 리전 | 계정 `493717844238`(AWS UserGroup Korea), 리전 `us-east-1` |
| 시험 자료 | AWSKRUG YouTube 채널(`https://www.youtube.com/@awskrug`)의 공개 영상을 내려받아 사용 |

## 결정의 배경과 조건

**녹화 형태.** AWSKRUG 밋업 녹화 영상에는 발표 화면이 함께 찍힙니다. 이 사실이 아래 화면 구성 1번의 전제입니다.

**세 가지 쇼츠 화면 구성.** 1번 구성은 녹화 영상에서 발표 화면 영역을 잘라 위쪽에 크게 놓고, 발표자 영역을 아래쪽에 놓습니다. 슬라이드 파일을 따로 받지 않고 녹화 화면에서 잘라 내므로, 영상 안에서 발표 화면과 발표자가 각각 어디에 있는지 알아야 합니다. 이 위치를 사용자가 지정하게 할지 자동으로 찾을지는 실제 녹화 영상을 확인한 뒤 정합니다. 2번 구성은 녹화 영상을 흐리게 확대한 배경 위에 원본 가로 영상을 가운데 놓습니다. 3번 구성은 녹화 영상의 가운데를 9:16으로 잘라 화면을 가득 채웁니다. 3번은 발표자가 화면 가운데에 있지 않으면 발표자가 잘립니다.

**한국어 자막.** 자막은 전사 결과를 그대로 입히므로 전사 오류가 화면에 보입니다. 렌더링 전에 사용자가 자막을 고치는 화면이 필요한지는 실제 전사 품질을 본 뒤 정합니다.

**팀 멤버 확인.** 사용자 범위를 조직 전체(2026-11-26 기준 76명)에서 팀으로 좁혔습니다. 권한 등급은 하나이며, 로그인할 수 있는 사람은 모든 기능을 쓸 수 있습니다.

**리전.** `us-east-1`을 쓰는 이유는 Amazon Bedrock의 모델 선택지가 가장 많기 때문입니다. 한국에서 수 GB 영상을 올리고 내려받는 속도는 서울 리전보다 느릴 수 있습니다. 업로드 속도가 문제가 되면 S3 Transfer Acceleration을 검토합니다. 이 계정의 `us-east-1`에는 2026-11-26 기준 CDK 부트스트랩이 되어 있지 않으므로 첫 배포 전에 `cdk bootstrap`을 실행해야 합니다. 부트스트랩 여부는 `ap-northeast-2`에서만 조회했고 `us-east-1`은 조회하지 않았으므로, 실행 전에 다시 확인합니다.

**웹 주소.** 이 AWS 계정의 Route 53에 `awskr.org` 호스팅 영역이 있습니다(2026-11-26 조회). `marketing.awskr.org` 레코드와 인증서는 CDK로 만듭니다. CloudFront에 붙이는 인증서는 `us-east-1`에 있어야 하는데, 배포 리전이 `us-east-1`이므로 같은 스택에서 만들 수 있습니다.

**시험 자료.** YouTube에서 내려받은 영상은 로컬 `samples/`에 두고 git에 올리지 않습니다. YouTube가 다시 인코딩한 영상이므로 원본 녹화 파일보다 화질이 낮을 수 있습니다.

## 아직 정하지 않은 것

1. **발표 화면과 발표자 영역의 위치를 정하는 방법.** 1번 화면 구성에 필요합니다. 실제 녹화 영상 몇 편의 화면 배치를 확인한 뒤 정합니다.
2. **쇼츠의 길이와 후보 개수.** 초안은 30-60초 구간 후보 5-8개입니다. 실제 결과를 보고 조정합니다.
3. **Bedrock 모델.** 환경 변수로 두고, 중간 등급 모델(Claude Sonnet 계열)에서 시작합니다. `us-east-1`에서 쓸 수 있는 모델 ID는 구현할 때 조회합니다.
4. **끝 화면에 쓸 자산.** `awskrug-digital-assets` 저장소에서 고릅니다. 어느 파일을 쓸지는 구현할 때 정합니다.
5. **영상 1편당 비용 한도.** 정해진 값이 없습니다. MVP에서 영상 1편의 실제 비용을 측정해 보고합니다.
6. **발표자 동의 절차.** MVP는 영상을 공개하지 않으므로 MVP를 막지 않습니다. YouTube 업로드를 만들기 전에 정해야 합니다.

## MVP 뒤의 순서

쇼츠 화면 구성을 정한 뒤 YouTube 비공개 업로드를 붙입니다. AWSKRUG YouTube 채널의 업로드 권한은 프로젝트 담당자가 갖고 있으므로, Google Cloud 프로젝트 생성과 OAuth 승인은 담당자가 직접 합니다. 그다음 슬라이드 동기화 영상을 만듭니다.
