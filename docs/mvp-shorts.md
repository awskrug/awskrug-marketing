# 첫 구현 범위: 쇼츠 MVP

이 문서는 2026-11-26에 프로젝트 담당자와 진행한 인터뷰의 결정 사항을 기록합니다. 첫 구현(MVP, 가장 먼저 동작하게 만들 최소 범위)은 쇼츠 자동 생성입니다. 슬라이드 동기화 영상과 YouTube 자동 업로드는 쇼츠 MVP 뒤에 만듭니다. 전체 설계는 [architecture.md](architecture.md)에 있고, 이 문서와 내용이 다르면 이 문서의 결정이 우선합니다.

## MVP가 끝났다고 보는 기준

`sns-working-group` 팀 멤버가 `marketing.awskr.org`에 GitHub 계정으로 로그인해 밋업 녹화 영상 파일을 올리면, 서비스가 핵심 구간 후보를 보여 줍니다. 사용자가 후보를 고르면 서비스가 그 구간을 세 가지 화면 구성의 세로(9:16) 쇼츠로 렌더링하고, 사용자가 결과 영상을 내려받을 수 있습니다. 이 흐름이 실제 AWSKRUG 밋업 녹화 영상 1편으로 처음부터 끝까지 동작하면 MVP가 끝난 것입니다.

MVP의 목적은 세 가지 화면 구성을 실제 결과물로 비교해 하나를 고르는 것입니다. 그래서 MVP는 고른 구간마다 세 구성을 모두 렌더링합니다. 구성을 정한 뒤에는 정한 구성만 렌더링하도록 바꿉니다.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 첫 구현 기능 | 쇼츠 자동 생성 |
| MVP에 포함 | 웹 화면, GitHub 로그인, 영상 업로드, 전사, 핵심 구간 후보 선정, 후보 선택, 렌더링, 결과 내려받기 |
| MVP에서 제외 | YouTube 자동 업로드, 슬라이드 동기화 영상, 슬라이드 파일 입력 |
| 사용자 범위 | GitHub `awskrug` 조직의 `sns-working-group` 팀 멤버만 로그인 가능 (2026-11-26 기준 5명) |
| 영상 입력 | 브라우저에서 파일 업로드만 지원. YouTube 주소 입력은 지원하지 않음 |
| 핵심 구간 처리 | 서비스가 후보를 보여 주고 사용자가 고른 구간만 렌더링 |
| 쇼츠 화면 구성 | 아래 세 가지를 모두 만들어 비교한 뒤 결정 |
| 브랜드 요소 | 로고 워터마크, 상단 제목 띠, 한국어 자막, 끝 화면 |
| 브랜드 자산 출처 | `awskrug/awskrug-digital-assets` 저장소 |
| 웹 주소 | `marketing.awskr.org` |
| AWS 계정과 리전 | 계정 `493717844238`(AWS UserGroup Korea), 리전 `ap-northeast-2`(서울) |
| 시험 자료 | AWSKRUG YouTube 채널(`https://www.youtube.com/@awskrug`)의 공개 영상을 내려받아 사용 |

## 결정의 배경과 조건

**녹화 형태.** AWSKRUG 밋업 녹화 영상에는 발표 화면이 함께 찍힙니다. 이 사실이 아래 화면 구성 1번의 전제입니다.

**세 가지 쇼츠 화면 구성.** 1번 구성은 녹화 영상에서 발표 화면 영역을 잘라 위쪽에 크게 놓고, 발표자 영역을 아래쪽에 놓습니다. 슬라이드 파일을 따로 받지 않고 녹화 화면에서 잘라 내므로, 영상 안에서 발표 화면과 발표자가 각각 어디에 있는지 알아야 합니다. 이 위치를 사용자가 지정하게 할지 자동으로 찾을지는 실제 녹화 영상을 확인한 뒤 정합니다. 2번 구성은 녹화 영상을 흐리게 확대한 배경 위에 원본 가로 영상을 가운데 놓습니다. 3번 구성은 녹화 영상의 가운데를 9:16으로 잘라 화면을 가득 채웁니다. 3번은 발표자가 화면 가운데에 있지 않으면 발표자가 잘립니다.

**한국어 자막.** 자막은 전사 결과를 그대로 입히므로 전사 오류가 화면에 보입니다. 렌더링 전에 사용자가 자막을 고치는 화면이 필요한지는 실제 전사 품질을 본 뒤 정합니다.

**팀 멤버 확인.** 사용자 범위를 조직 전체(2026-11-26 기준 76명)에서 팀으로 좁혔습니다. 권한 등급은 하나이며, 로그인할 수 있는 사람은 모든 기능을 쓸 수 있습니다.

**리전.** 배포 리전은 `ap-northeast-2`(서울)입니다. 처음에는 Amazon Bedrock의 모델 선택지가 많다는 이유로 `us-east-1`을 골랐으나, 2026-11-27에 프로젝트 담당자가 서울 리전으로 바꿨습니다. 이 서비스는 한국에서 수 GB 영상을 올리고 내려받으므로 전송 거리가 짧은 리전이 유리하기 때문입니다. 같은 날 서울 리전에 CDK 부트스트랩을 실행했고(`CDKToolkit` 스택, 부트스트랩 버전 34), `us-east-1`에 만들었던 시험용 S3 버킷과 Transcribe 작업은 삭제했습니다. Bedrock은 서울 리전에서 전역 추론 프로필 `global.anthropic.claude-sonnet-4-6`을 호출하며, 2026-11-27에 호출되는 것을 확인했습니다. 전역 추론 프로필은 요청을 다른 리전에서 처리할 수 있으므로, 전사문이 한국 밖에서 처리되어도 되는지는 따로 판단해야 합니다. 서울 리전에서의 전사와 후보 선정 전체 실행은 아직 하지 않았습니다.

**웹 주소.** 이 AWS 계정의 Route 53에 `awskr.org` 호스팅 영역이 있습니다(2026-11-26 조회). `marketing.awskr.org` 레코드와 인증서는 CDK로 만듭니다. CloudFront에 붙이는 인증서는 `us-east-1`에 있어야 합니다. 배포 리전이 서울이므로 인증서만 `us-east-1`에 만드는 별도 스택이 필요하고, 그 스택을 배포하려면 `us-east-1`에도 CDK 부트스트랩이 필요합니다. `us-east-1`은 2026-11-27 기준 부트스트랩되어 있지 않습니다.

**시험 자료.** YouTube에서 내려받은 영상은 로컬 `samples/`에 두고 git에 올리지 않습니다. YouTube가 다시 인코딩한 영상이므로 원본 녹화 파일보다 화질이 낮을 수 있습니다.

## 처리 코드 구현과 첫 실측 (2026-11-27)

처리 코드는 `services/shorts/`에 Python 패키지와 명령줄 도구로 구현했습니다. 설계와 구현 계획은 [plans/2026-11-26-shorts-processing.md](plans/2026-11-26-shorts-processing.md)에, 사용법은 [services/shorts/README.md](../services/shorts/README.md)에 있습니다. 아래 내용은 AWSKRUG DevOps 소모임 녹화 영상 1편(2026-09-15 촬영, 1920x1080, 39분 50초)으로 2026-11-27에 측정한 결과입니다. 영상 1편의 결과이므로 다른 녹화에서도 같다고 볼 수는 없습니다.

**녹화 화면의 배치.** 이 영상은 강의실 객석에서 손으로 든 카메라로 찍었습니다. 카메라 위치와 줌이 여러 번 바뀌고, 45초 구간 안에서도 발표 화면의 위치가 움직입니다. 발표 화면은 비스듬하게 찍히고 청중의 머리에 일부 가려집니다. 같은 채널의 Community Day 2025 영상 2편은 발표자와 슬라이드 위치가 고정된 합성 화면이었습니다. 따라서 녹화 방식은 행사마다 다릅니다.

**전사.** Amazon Transcribe(한국어)가 39분 50초 분량을 2분 15초에 전사했습니다. 영상 대신 영상에서 뽑은 음성 파일(37MB)을 올렸습니다. 강의실 녹음이라 오인식이 눈에 띄며, 자막을 고치지 않고 내보내기는 어려운 품질입니다.

**구간 후보 선정.** `us-east-1`에서 Claude Sonnet 4.6(`us.anthropic.claude-sonnet-4-6`)으로 13초가 걸렸고 후보는 2개가 나왔습니다(상한 8개, 각 45.6초와 50.9초). 사용량은 입력 23,048토큰, 출력 1,132토큰입니다. 이 계정에서는 Claude 4.7 이후 모델의 호출이 거부됩니다. 2026-11-27에 모델별로 호출해 확인했으며, 호출되는 모델은 Opus 4.6, Sonnet 4.6, Opus 4.5, Haiku 4.5입니다. 그래서 기본 모델을 Sonnet 4.6으로 정했습니다.

**렌더링.** 후보 하나를 세 구성으로 렌더링하는 데 로컬 컴퓨터(Apple Silicon)에서 약 1분 40초가 걸렸습니다. 컨테이너에서의 소요 시간은 측정하지 않았습니다.

**세 구성을 비교한 결과.** 1번 구성(발표 화면 위, 발표자 아래)은 카메라가 움직이기 때문에 영역을 넉넉하게 잡아야 하고, 그러면 슬라이드 본문 글자가 작아져 읽기 어렵습니다. 2번 구성(흐린 배경 위 원본)은 장면 전체가 보이지만 원본이 화면의 3분의 1 높이만 차지합니다. 3번 구성(가운데 절단)은 청중의 뒷모습이 화면을 채우고 발표자가 보이지 않아 이 녹화 방식에는 맞지 않습니다. 어느 구성을 쓸지는 프로젝트 담당자가 결과 영상을 보고 정합니다.

**비용.** 영상 1편의 비용은 Transcribe 약 $1, Bedrock 약 $0.09로 추정합니다. 이 값은 응답에 기록된 사용량에 단가를 곱한 추정이며, 단가를 요금표에서 확인하지 않았고 실제 청구액도 확인하지 않았습니다.

**시험용 AWS 리소스.** 이 측정은 `us-east-1`에서 했습니다. 측정에 쓴 시험용 S3 버킷과 Transcribe 작업은 서울 리전으로 옮기기로 한 2026-11-27에 삭제했습니다. 음성 파일과 전사 결과의 사본은 로컬 `samples/`에만 있습니다.

## 아직 정하지 않은 것

1. **발표 화면과 발표자 영역의 위치를 정하는 방법.** 2026-11-27에 정했습니다. 구간 후보마다 사용자가 대표 프레임에서 두 영역을 사각형으로 지정하고, 구간 안의 카메라 움직임을 덮도록 넉넉하게 잡습니다. 카메라 움직임을 자동으로 따라가는 방법은 화면 구성을 정한 뒤 검토합니다.
2. **쇼츠의 길이와 후보 개수.** 초안은 30-60초 구간 후보 5-8개입니다. 실제 결과를 보고 조정합니다.
3. **Bedrock 모델.** 2026-11-27에 Claude Sonnet 4.6으로 정했습니다. 환경 변수 `SHORTS_BEDROCK_MODEL_ID`로 바꿀 수 있습니다. 후보가 2개만 나온 원인은 2026-11-27에 확인해 고쳤습니다. 모델은 8개를 제안했지만 구간 길이를 잘못 계산해 5개가 60초 상한을 넘었고(82-101초), 응답 검증 코드가 이를 버리고 있었습니다. 지금은 상한을 넘는 구간을 버리지 않고 끝 문장부터 줄여 상한에 맞춥니다. 같은 전사문으로 서울 리전에서 다시 실행한 결과 후보 8개(43.7-57.3초)가 나왔습니다. 끝 문장이 잘린 후보의 내용이 자연스럽게 끝나는지는 영상으로 확인하지 않았습니다.
4. **끝 화면에 쓸 자산.** `awskrug-digital-assets` 저장소에서 고릅니다. 어느 파일을 쓸지는 구현할 때 정합니다.
5. **영상 1편당 비용 한도.** 정해진 값이 없습니다. MVP에서 영상 1편의 실제 비용을 측정해 보고합니다.
6. **발표자 동의 절차.** MVP는 영상을 공개하지 않으므로 MVP를 막지 않습니다. YouTube 업로드를 만들기 전에 정해야 합니다.

## MVP 뒤의 순서

쇼츠 화면 구성을 정한 뒤 YouTube 비공개 업로드를 붙입니다. AWSKRUG YouTube 채널의 업로드 권한은 프로젝트 담당자가 갖고 있으므로, Google Cloud 프로젝트 생성과 OAuth 승인은 담당자가 직접 합니다. 그다음 슬라이드 동기화 영상을 만듭니다.
